# Auto Mailer — учебный каркас

Это намеренно незавершённый проект. Готовая логика рассылки удалена: твоя
задача — реализовать её самостоятельно по `TODO`-комментариям, а затем
прислать изменения на проверку.

В исходниках и сборке Qt не используется. Qt Creator можно использовать только
как IDE. Потоки реализуются средствами стандартного C++ через `std::thread`.
Для базы данных позже подключим SQLite как отдельную внешнюю библиотеку.

## Как работать

1. Открой проект в Qt Creator.
2. Выполняй задания по порядку, не переписывая всё сразу.
3. После каждого задания собирай проект.
4. Присылай мне изменённый файл или ошибку сборки — я буду проверять код,
   объяснять недочёты и давать следующее задание.

## Задания

### 1. Шаблонизатор

Реализуй `TemplateRenderer<Context>::render()` в
`include/domain/template_renderer.h`.

Поддерживаемый синтаксис: `{{name}}` и `{{ email }}`. Сохрани обычный текст,
замени переменные через `Resolver` и отдельно реши поведение неизвестных
переменных.

### 2. Репозиторий SQLite

Реализуй методы `MailRepository` в
`src/db/mail_repository.cpp`:

- уникальное соединение SQLite;
- корректное закрытие и удаление соединения;
- создание таблиц;
- параметризованные INSERT-запросы;
- транзакцию для демонстрационного наполнения;
- JOIN для чтения очереди;
- параметризованный UPDATE статуса.

Соединение репозитория должно создаваться в том потоке, где оно используется.
Не передавай SQLite-дескриптор из `main()` в рабочий поток.

### 3. Dry-run отправитель

Реализуй `DryRunMailSender::send()`. Он должен только печатать письмо и
возвращать `Success`, не выполняя сетевых операций.

### 4. Рабочий поток

Реализуй `MailWorker::process()` в
`src/mail/mail_worker.cpp`. Он должен читать очередь, рендерить шаблон,
вызывать отправитель и отмечать задачу отправленной только после успеха.

### 5. Запуск через `std::thread`

Реализуй код в `main.cpp`: создай объекты через `std::unique_ptr`, перемести
worker в lambda для `std::thread` и дождись завершения через `join()`.
Объясни в комментарии, почему `detach()` здесь опасен.

## Сборка

Нужны Qt 6 с модулями `Core` и `Sql`, а также CMake 3.21+.

```powershell
cmake -S . -B build
cmake --build build --config Debug
```

## Важные ограничения

Сейчас используется только dry-run. Реальный SMTP подключим после проверки
архитектуры. Пароли нельзя хранить в исходниках или обычном виде в базе;
позже разберём OAuth2 или пароль приложения, ограничения скорости, повторы и
отказ от рассылки.
